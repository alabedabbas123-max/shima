# إصلاح ربط المحلّل في مشروع sh129

هذا التصحيح خاص بأرشيف التطبيق `sh129.zip` الذي أرسله صاحب المشروع، وليس تحديثاً لواجهة SDK ولا ملف APK جاهزاً. بصمة SHA-256 للأرشيف الذي طُبّق عليه التصحيح:

```text
c17b0635e64cb55cda8a0c69d1afcee357a9b7f79e285d76a08041a916d562f8
```

## ما وجدناه

سجل `StackOverflowError` يبيّن حلقة في ربط التطبيق: تحرير الجسر ينشر التشخيصات، وعرضها يبلّغ التركيز، فيُعاد تحرير الجسر. لا تظهر أصناف SDK في الإطارات المتكررة. وفحصنا مصادر SDK الموجودة في الأرشيف: ملفات Java الـ34 مطابقة لنسخة SDK في هذا المستودع، و`AnalysisHandle.close()` يعلّم الجلسة مغلقة قبل فصل الاشتراك ولا ينشر النتائج مباشرة.

**نسخة `sh129.zip` كانت تحتوي بالفعل إجراءات لمنع الحلقة**، منها `EditorFocusEdge` ومنع النشر عند عدم وجود حالة وحارس إعادة الدخول في النشاط. أرقام أسطرها لا تطابق أرقام السجل القديم. لا نستطيع تحديد أي APK مثبّت على جهازك من المصدر وحده.

وجدنا باختبار المضيف مشكلة إضافية في الربط الحالي: قد تُتجاهل إشارة تركيز جديدة حقيقية إذا وصلت أثناء نشر الجسر. في محاكاة انتقال `A → B → C` أثناء النشر بقي الجسر على `B` مع أن المحرر على `C`. التصحيح يحافظ على آخر حدث ويرسله بعد انتهاء الاستدعاء الجاري، مع الإبقاء على منع تكرار حدث الرسم نفسه الموجود في `EditorFocusEdge`.

## محتويات التعديل

- `MainActivity.java`: تجميع آخر إشارة تركيز/تعديل على طابور الواجهة، وعدم فقد التعديل، وإلغاء الإشارات القديمة عند إغلاق المشروع أو آخر تبويب؛ يبدأ الفحص الجماعي الناجم عن التعديل بعد تبنّي الجسر لأحدث تبويب.
- `AnalyzerSignalQueue.java`: طابور صغير يقبل مهمة واحدة معلّقة، ويستخدم جيلاً لإبطال المهام القديمة؛ لا يُغني وحده عن حاجز التكرار الموجود أصلاً في المحرر.
- `AnalyzerBridge.java`: ترحيل إشعار واجهة قد يصدر من خيط فحص المشروع إلى الخيط الرئيسي، وربط تحذير غياب JNI بالملف الصحيح حتى يُمسح عند الإغلاق.
- `qa/AnalyzerSignalQueueRegression.java` و`qa.sh`: فحوص للانتقالات، والإلغاء، وحالة وجود JNI وغيابه. لم نعدّل شفرة SDK التشغيلية.

## طريقة التركيب

**اختر طريقة واحدة فقط**، واحتفظ بنسخة احتياطية. تنطبق الملفات على أرشيف `sh129.zip` المطابق للبصمة أعلاه؛ لا تستبدل بها ملفات نسخة أحدث معدّلة دون مراجعة الفروق.

### 1. تطبيق التصحيح

فك أرشيف المشروع الأصلي، وضع `focus-and-diagnostics.patch` بجانب مجلد المشروع، ثم من داخل مجلد المشروع الذي يحتوي `app/`:

```sh
git apply --check ../focus-and-diagnostics.patch
git apply ../focus-and-diagnostics.patch
```

يمكن استعمال `patch -p1 < ../focus-and-diagnostics.patch` بدلاً من `git apply` عند توفر أداة `patch`. إذا فشل الفحص لا تفرض التطبيق؛ فهذا يعني أن ملفات المشروع لا تطابق النسخة التي فُحصت.

### 2. استبدال الملفات يدوياً

فك `sh129-fixed-files.zip` **داخل جذر نسخة من مشروع sh129 غير المعدّلة**، ووافق على استبدال الملفات ذات المسارات المتطابقة. الأرشيف يحتوي فقط الملفات المتغيرة والاختبار والإرشادات، ولا يحتوي المشروع كله، ولا ملفات التوقيع، ولا AAR أو APK.

### البناء والتجربة

استخدم بيئة بناء المشروع الأصلية: JDK 17 وAndroid SDK بالمنصة وأدوات البناء المحددتين في ملفات Gradle الخاصة بالمشروع، والاعتماديات اللازمة. على جهازك:

```sh
./gradlew --no-daemon --no-build-cache --rerun-tasks :app:assembleDebug
```

أو أعد بناء التطبيق من Android Studio. ثبّت **APK الناتج الجديد** بنفس مفتاح توقيع النسخة المثبتة إن أردت تحديثها مع الاحتفاظ ببياناتها، ثم جرّب: تشغيل بلا مشروع، فتح Java ثم Kotlin/XML، التبديل السريع، التعديل، إغلاق آخر تبويب، وإغلاق المشروع وإعادة فتحه. لا تحذف التطبيق أو بياناته تلقائياً إذا تعذّر التحديث بسبب اختلاف التوقيع.

الأرشيف الأصلي يشحن ملفات JNI لـ`arm64-v8a` و`x86_64` فقط؛ أي ABI آخر يحتاج ملفه الموافق. لم نغيّر هذه الثنائيات.

## حدود التحقق

- اختبارات SDK على المضيف: 350 فحصاً ناجحاً، بينها الإغلاق المعاد دخوله والإغلاق من callback.
- فحوص ربط التطبيق: 20 مع JNI للمضيف، و20 عند غيابه، و3 لتحويل إشعار العامل إلى الخيط الرئيسي؛ فُحص تركيب ملفات Java الثلاثة بالمحلّل فقط، لا بمترجم Android.
- اختبارات التطبيق الموجودة المتعلقة بالصدى وحافة التركيز وبراءة SDK: 21 فحصاً ناجحاً مع JNI و21 دون JNI، بعد تكييف مسار اختبار المضيف لبيئة التشغيل.
- لم يُبنَ APK أو AAR هنا ولم تُجرَ تجربة على جهاز Android. لم تكتمل مجموعة `qa.sh` الكاملة في البيئة المؤقتة: تتوقع حزم تسليم محلية، وJRE المستخدم للاختبار لا يوفّر `SystemJavaCompiler`. لا تُعدّ الاختبارات الجزئية إثباتاً لنجاح المجموعة الكاملة أو تشغيل التطبيق على الجهاز.

لإعادة فحوص الربط المستقلة على Linux، من مستودع SDK ومع توفر JDK 17 ورؤوس JNI وC compiler:

```sh
./scripts/test-sh129-integration.sh /path/to/sh129.zip
```
