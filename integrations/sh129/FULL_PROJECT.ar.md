# مشروع sh129 الكامل بعد تحديث الفحص

هذه نسخة **مصدر المشروع الكامل**، لا APK أو AAR جاهز. تحتوي التطبيق وموارده وملفات Gradle و`gradlew` ووحدة `analyzer` ومصادر محللاتها، مع تعديلات الربط والاختبارات. أُعدّت من `sh129.zip` ذي البصمة:

`c17b0635e64cb55cda8a0c69d1afcee357a9b7f79e285d76a08041a916d562f8`

## قبل البناء

1. لم تُدرج مفاتيح التوقيع أو كلماتها؛ أُزيل إعداد المفتاح الثابت من `app/build.gradle`، واستُبدل التوقيع الخاص في أحد التقارير بنص محجوب. بناء debug يستخدم مفتاح debug الخاص ببيئتك، وrelease لا يملك هنا توقيعاً للإصدار. لتحديث تطبيق مثبت والحفاظ على بياناته تحتاج إعداد التوقيع الأصلي المناسب بشكل آمن؛ لا تحذف التطبيق أو تغيّر مفتاحه عشوائياً.
2. حُذفت ملفات JNI القديمة المبنية مسبقاً لأنها لا تطابق بروتوكول أحداث المحلل الجديد. أصبحت وحدة `analyzer` تبني `libshima_analyzer.so` من المصدر عبر CMake وNDK عند بناء التطبيق. لا تنسخ ملفات `.so` القديمة إلى `app/src/main/jniLibs`، كي لا يتكرر الملف أو يعمل إصدار قديم.
3. افتح جذر المشروع في Android Studio. يلزم JDK 17 وAndroid SDK/Build Tools 37 كما في المشروع الأصلي، وNDK `25.1.8937393` وCMake `3.22.1`، واعتماديات Gradle/AndroidX والاتصال المطلوب لجلبها. من جذر المشروع:

```sh
./gradlew --no-daemon :app:assembleDebug
```

الإعدادات مهيأة لإعادة بناء JNI للمعماريات `armeabi-v7a`, `arm64-v8a`, `x86`, `x86_64`. **لم نتمكن من بناء APK/AAR أو تجربته على هاتف أو محاكي في هذه البيئة**؛ تأكد من البناء والتثبيت والأداء ودورة الحياة لديك. لا يوجد APK داخل هذه الحزمة.

## ما عُدّل وما بقي

- يبقى الخطأ السابق معلّقاً بعد التعديل أو فشل المحلل، مع تعطيل إصلاحه القديم، حتى تثبت نتيجة أحدث إصلاحه. أسباب الفحص الجزئي مميزة، وتغيّر السبب لا يُبقي رسالة الحجم القديمة. اختُبر أيضاً حذف الملف بعد مسح كامل، والإبقاء على الصف معلّقاً عند تعذر المسح.
- تحليل أعضاء Java من مصادر المشروع يتتبع المستقبلات وسلسلة الوراثة المؤكدة، ويكشف أمثلة مثل `this.clibs.getKay()` عند توفر مصادر كافية؛ لا ينفي وجود عضو في أب أو مكتبة غير معروفين. لا يفحص SDK توافق جميع معاملات overloads أو أعضاء المكتبات.
- تحذيرات unused صفراء وخارج لوحة الأخطاء الحرجة. أُوقف فحص imports النصي الخام الذي كان قد يخلق أخطاء في التعليقات والثوابت، كما لا تُطبّق تخمينات الأقواس العامة على ملفات Gradle/HTML/النص غير المدعومة. لهذه الحالات قد تنقص التشخيصات بدلاً من اختراعها.
- SDK يدعم Java/Kotlin/XML بفحوص محدودة؛ لمسار التطبيق القديم دعم Smali مستقل، بينما ملفات Groovy/Gradle والأنواع الأخرى **ليست محلّلة تحليلاً شاملاً**. لا يتحقق هذا التسليم من كل أنواع الملفات أو كل محتويات الملفات الكبيرة: حد ملف workspace في ربط التطبيق 200,000 وحدة UTF-16، وتُعلن الجزئية عند تجاوز حد أو تعذر القراءة. المشروع يقسّم إلى دفعات، والفهرس بين الدفعات غير شامل. العلامات المعلّقة تقريبية وليست دليلاً على بقاء الخطأ.
- ما يخص API والاعتماديات يظل مشروطاً بصحة بيانات المشروع والـclasspath؛ لا يوجد حل كامل لـGradle وvariants أو قاعدة شاملة لتواقيع Android. Unicode escapes التي تغير حدود الرموز في Java تعطي `PARTIAL` بدلاً من الادعاء بدقة معالجة javac.
- يجري فحص SDK في عامل خلفي؛ وتستخدم قناة التطبيق القديمة الخدمة المعلنة في عملية `:analyzer`. اختبارات المضيف لا تثبت استحالة تعليق الواجهة أو عزل جميع خدمات التطبيق على الأجهزة.

نجحت اختبارات Linux المستهدفة باستخدام JNI للمضيف وبدائل Android/Messenger، لكنها لا تحل محل بناء Android أو مجموعة QA الكاملة أو اختبارات مشاريعك الفعلية. تفاصيل SDK: مجلد `analyzer/docs`، وتقارير المستودع ودليل تطبيق الـpatch: `https://github.com/alabedabbas123-max/shima/blob/arena/e4720c12-shima/integrations/sh129/QUALITY.ar.md`.
